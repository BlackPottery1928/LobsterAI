# 登录介绍页测试方案

## 展示条件与本地标识

首次启动入口需要同时满足：未登录、原有首次使用流程未完成、介绍页未展示过，以及启动引擎/更新遮罩已结束。

| 标识 | 含义 | 对自动展示的影响 |
| --- | --- | --- |
| `privacy_agreed` | 原有首次使用/隐私确认流程的持久化标识 | 为 `true` 时，不进入首次使用流程，因此也不展示介绍页 |
| `login_introduction_seen` | 本次新增的介绍页已展示标识 | 为 `true` 时，跳过介绍页，继续原有操作引导 |

两个标识通过 `window.electron.store` 读写，保存在 Electron 用户数据目录的 `lobsterai.sqlite` 的 `kv` 表中。Windows 默认路径是 `%APPDATA%\LobsterAI\lobsterai.sqlite`，不在浏览器 `localStorage` 中。

`login_introduction_seen` 在页面首次展示时就写为 `true`，无需点击关闭或完成登录。退出账号不清除这两个标识，因此退登、重启均不会自动重现介绍页。保留应用数据的重新安装也不等同于全新设备。

## 在现有安装上重新触发

1. 使用包含本次改动的客户端，并先在界面中退出账号。
2. 打开客户端渲染进程的 DevTools Console。开发环境可关闭现有开发进程后，在仓库根目录运行 `npm run electron:dev:inspect`，自动打开 DevTools。首次搭建环境仍需按仓库说明准备 OpenClaw runtime。
3. 如需检查现状，在 Console 执行：

   ```js
   console.table({
     privacy_agreed: await window.electron.store.get('privacy_agreed'),
     login_introduction_seen: await window.electron.store.get('login_introduction_seen'),
   });
   ```

4. 在同一个 Console 执行下面的代码，模拟尚未完成首次使用流程的设备：

   ```js
   await window.electron.store.set('privacy_agreed', false);
   await window.electron.store.set('login_introduction_seen', false);
   window.location.reload();
   ```

5. 等待启动/更新遮罩结束，应该出现左侧轮播、右侧登录按钮的介绍页。

这段代码只重置两个引导标识，不删除会话或模型配置。它也会让原有操作引导重新出现。每次需要从介绍页重新测试时，先确认已退登，再重复第 4 步；只重置 `login_introduction_seen` 无法绕过 `privacy_agreed=true` 的入口条件。

若仍未出现，检查运行的是否为本分支代码、是否仍处于已登录状态，以及启动/更新遮罩是否结束。企业受管配置可能自动完成首次使用确认，不适合作为个人版新设备的测试环境。

## 手工验收用例

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 首次展示 | 退登，重置两个标识并重新加载 | 启动遮罩结束后显示介绍页；查看存储时 `login_introduction_seen` 已为 `true` |
| 自动轮播 | 鼠标与键盘焦点移出左侧轮播，保持窗口可见 | 每 5 秒切换一张；共 10 个场景，图片、标题、说明和示例文件对应 |
| 手动切换 | 点击圆点、左右按钮；焦点在轮播内时按左右方向键 | 切换到对应场景，首尾循环；图片完整加载 |
| 暂停轮播 | 鼠标悬停或键盘焦点进入轮播；最小化窗口；启用系统减少动态效果 | 相应情况下暂停自动播放；解除条件后恢复，减少动态效果启用期间保持暂停 |
| 跳过登录 | 点击右上角浅灰 X；重新触发后再测试 Escape | 关闭介绍页，不唤起浏览器，继续原有操作引导；后续可完成或跳过原有引导 |
| 展示一次 | 首次展示后直接重新加载/重启，不点登录或 X | 不再展示介绍页；首次使用尚未完成时显示原有操作引导 |
| 登录成功 | 重新触发，点击“立即登录”，在系统浏览器完成登录并返回客户端 | 请求处理中按钮禁用；成功唤起浏览器后结束介绍页；登录回调更新账号并延续原有欢迎任务流程 |
| 登录请求失败 | 测试环境使启动登录请求返回失败，再点击登录 | 显示失败提示、介绍页保留、按钮恢复可用，能够重试 |
| 取消网页登录 | 浏览器正常打开后不完成认证，返回客户端 | 不会卡在介绍页，沿用原有未登录返回处理 |
| 老用户/退登 | 将 `privacy_agreed` 设为 `true`，保持未登录并重新加载；另外验证正常登录后退登 | 不自动展示介绍页，即使 `login_introduction_seen` 不存在或为 `false` |
| 布局与文案 | 测试 1280×800、800×600，中文/英文、浅色/深色主题 | 文案可读、按钮和关闭入口可见、卡片不溢出；Windows 标题栏操作正常 |
| 键盘操作 | Tab、Shift+Tab 遍历控件，再按 Escape | 焦点保持在弹窗内，焦点样式可见，Escape 可关闭 |

聊天中的登录提示也复用本次新样式：未登录且没有可用的自定义模型时，发送需要登录才能使用的模型请求，会触发该提示。这个入口由聊天操作触发，不受首次展示标识限制；仅退出账号或点击其他登录入口不保证打开它。

## 验证记录

实现阶段已通过：生产构建、TypeScript 检查、修改文件的 ESLint、4 个相关 Vitest 文件的 49 项测试，以及本地 Electron 组件冒烟的 18 项检查。另已在独立的新用户数据目录中启动真实客户端，检查首次展示、X 跳过和 SQLite 标识持久化。

真实账号的浏览器认证与回调尚未实测，需按上述“登录成功”用例完成验收。本地预览脚本、测试数据目录、日志和截图不随生产代码提交。
