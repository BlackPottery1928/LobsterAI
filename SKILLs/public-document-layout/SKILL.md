# 政党机关公文排版助手

这是一套“先判型、再排版、后验收”的公文文档处理 Skill。核心目标不是把文字机械套进模板，而是根据文种、用途和原稿结构，自动选择合适的版式策略，再输出可编辑、可复查、尽量接近正式办公要求的 DOCX。

## 设计原则

1. **标准优先**：党政机关公文优先遵循 GB/T 9704-2012；电子显现相关事项结合 GB/T 33476.2-2016。
2. **内容不擅改**：默认只处理结构、格式、标点和必要的版式清理，不擅自改写事实、数字、政策表述。
3. **原稿可逆**：排版现有文件时输出新文件，不覆盖原稿。
4. **对象保护**：图片、表格、超链接、批注、嵌入对象等尽量原位保留；无法安全重排的对象优先保护而非破坏。
5. **规则分层**：把“国家标准格式”“机关内部材料版式”“视觉优化样式”明确区分，避免把非标准装饰误称为国标。
6. **结果验收**：生成后至少执行文档结构、页面、字体、段落、页码、版记等自动检查；发现问题自动修复一轮。

## 能做什么

### A. 正式公文
- 通知、请示、报告、函、批复、通报、决定、意见、公告、通告、议案、纪要、命令（令）、公报等。
- 红头、白文、空红头、联合行文、上行文签发人、份号、密级、紧急程度、发文字号、主送机关、附件说明、附注、抄送、印发信息、页码。

### B. 政务材料
- 工作汇报、情况报告、经验材料、调研材料、讲话稿、发言稿、会议材料、学习材料、交流材料、实施方案、工作要点、行动方案、制度办法等。
- 对这些材料，默认采用“政务材料版式”，不把它们强行伪装成国家标准公文。

### C. 文档重排与修复
- 从 DOCX/TXT/MD 读取原稿并重新排版。
- 纠正常见字体串用、段距混乱、首行缩进异常、编号层级错乱、页码失效、版记继承页脚等问题。
- 在保留内容的基础上修复版面结构。

### D. 质检
- 自动检查纸张尺寸、页边距、主要字号、正文行距、标题层级、页码字段、版记页脚、异常空段等。
- 输出 `检查报告`，区分“硬错误 / 风险项 / 可优化项”。

# 二、版式方案库

> 方案的意义是控制排版策略，不等于每种方案都属于 GB/T 9704-2012 的正式格式。

## 2.1 标准公文 / `official`

适用于通知、请示、报告、函、批复、通报、决定、意见等正式公文。

核心参数：
- A4
- 上 37mm、下 35mm、左 28mm、右 26mm
- 标题 2 号小标宋体类字体，居中
- 正文 3 号仿宋类字体
- 一级标题黑体、二级标题楷体、三级标题仿宋
- 正文固定值行距按目标单位要求配置，默认 28pt
- 段前段后 0
- 页码使用独立页脚处理
- 正式公文要素按文种规则启用

## 2.2 红头公文 / `red`

在 `official` 基础上加入发文机关标志、红色分隔线、发文字号等版头要素。

可组合：
- 单机关
- 联合行文
- 上行文 + 签发人
- 份号
- 密级及保密期限
- 紧急程度

## 2.3 空红头 / `red_space`

保留正式红头纸使用所需的版头占位结构，不生成虚构机关名称。

## 2.4 信函格式 / `letterhead`

适用于标准所列信函格式。版头高度与正式公文不同，正文结构保持简洁。

## 2.5 命令格式 / `order`

针对命令（令）设置独立版头逻辑，不直接套用普通通知模板。

## 2.6 纪要格式 / `minutes`

针对会议纪要单独处理会议名称、会议时间、地点、参会人员、主持人、议定事项等结构。

## 2.7 政务材料 / `briefing`

用于汇报、讲话、研讨、调研、工作总结、经验交流等非严格公文。允许更清晰的视觉层级，但不伪装成国标正式公文。

## 2.8 制度方案 / `policy`

用于制度、办法、细则、方案、要点、清单类材料。重点强化多级标题、条款编号、表格与附件结构。

## 2.9 会议材料 / `meeting`

用于议程、主持词、发言提纲、会议手册等。默认以可读性和打印稳定性优先。

## 2.10 极简行政 / `minimal`

用于内部流转材料。减少无必要的装饰、空白和视觉噪声，强调高密度信息阅读。

# 三、视觉风格集

当用户没有要求严格国标、而是需要“正式、好看、适合领导审阅”时，从下列风格中选择：

| 风格 | 特征 | 适用 |
|---|---|---|
| 01 标准严谨 | 黑白、层级克制、重规范 | 正式发文 |
| 02 清正文务 | 空间略舒展、标题更清楚 | 汇报材料 |
| 03 稳重政务 | 标题层级更醒目、正文紧凑 | 工作报告 |
| 04 会议纪要 | 信息块清晰、要点密集 | 会议材料 |
| 05 制度条款 | 编号清楚、条款结构强 | 制度办法 |
| 06 调研报告 | 摘要/正文/建议结构明显 | 调研材料 |
| 07 讲话材料 | 标题简洁、段落舒展 | 讲话稿 |
| 08 极简黑白 | 不加视觉装饰 | 内部流转 |

正式公文使用 `01 标准严谨`；其他视觉风格只有在任务属于非严格标准材料时才启用。

# 四、文种智能判型

## 优先识别

| 文种 | 典型特征 | 重点排版 |
|---|---|---|
| 通知 | 发布事项、部署工作、周知事项 | 标准主体结构 |
| 请示 | 请上级批准、解决问题 | 上行文、签发人 |
| 报告 | 汇报工作、反映情况 | 上行文、签发人 |
| 函 | 平行机关商洽、询问、答复 | 信函/标准函件 |
| 批复 | 回复请示 | 规范标题、复函主体 |
| 通报 | 表彰、批评、传达情况 | 事实与评价层级 |
| 决定 | 对重要事项作出决策 | 条款式主体 |
| 意见 | 指导、部署、提出意见 | 多级层次 |
| 公告/通告 | 向社会或特定范围公布 | 公布性格式 |
| 纪要 | 记录会议议定事项 | 会议要素 |
| 命令 | 依法发布命令 | 专用格式 |
| 议案 | 向权力机关提请审议 | 议案结构 |

### 冲突处理

当标题与正文特征冲突时：
1. 优先采用用户明确指定的文种。
2. 用户未指定时，再根据标题、首段、结尾和行文对象综合判断。
3. 判断仍不确定时使用 `official_generic`，不虚构文种属性。

# 五、正文识别规则

自动识别以下常见层级：

```text
一、……
（一）……
1. ……
（1）……
① ……
```

同时识别：
- “第一，”
- “首先、其次、再次、最后”
- “一是……二是……”
- “附件：”
- “附：”
- 表格前后的说明文字

### 接排规则

遇到：

```text
（一）总体要求。坚持……
```

将“（一）总体要求。”作为标题部分，“坚持……”按正文部分处理，避免整句被错误套成标题字体。

### 标题保护

以下内容默认不进行过度拆分：
- 《书名号》中的句号
- 日期、编号中的数字
- URL
- 版本号
- 小数
- 表格内容
- 超链接文本

# 六、正式公文要素

根据文种和用户输入按需生成：

- 份号
- 密级和保密期限
- 紧急程度
- 发文机关标志
- 发文字号
- 签发人
- 红色分隔线
- 标题
- 主送机关
- 正文
- 附件说明
- 发文机关署名
- 成文日期
- 印章占位
- 附注
- 附件
- 抄送机关
- 印发机关
- 印发日期
- 页码

### 数据清洗

排版前只做安全清洗：
- 删除明显多余的制表符
- 统一连续空格
- 统一常见全角/半角标点
- 修复成对中文引号
- 保护机关代字、年份、文号等关键字符串

不得未经授权：
- 修改数字事实
- 修改政策名称
- 修改机构名称
- 擅自替换联系人、电话
- 擅自删减正文

# 七、现有 DOCX 重排规则

1. 先复制原文件。
2. 扫描段落、表格、图片、超链接和分页结构。
3. 建立对象保护清单。
4. 仅处理纯文本段落的格式。
5. 图片/图表所在段落优先跳过格式重建。
6. 表格使用表格专属规则，不把正文首行缩进套进去。
7. 重新建立页脚时先解除节链接。
8. 保存到新文件。
9. 二次读取输出文件进行验证。

输出文件建议：

```text
（公文排版）原文件名.docx
```

发生二次处理时：

```text
（公文排版2）原文件名.docx
```

绝不覆盖用户原稿。

# 八、分页与页码策略

## 页码

正式公文：
- 启用奇偶页不同
- 奇数页与偶数页分别定位
- 使用 Word PAGE 域，而非静态数字
- 在文档设置中启用字段更新
- 版记页不继承正文页码
- 首页面码依据所选版式决定

## 分页

自动避免：
- 标题孤行
- 一级标题落在页尾
- 附件说明与附件内容完全分离
- 版记被截断
- 表格标题与表格分离

当自动分页无法满足时，优先调整自然段分页控制，而不是堆叠空行。

---

# 九、表格与图片策略

## 表格

- 表格整体居中或按原稿保持对齐
- 表格正文不套用正文首行缩进
- 单元格内文字按表格语义选择字号
- 防止表格跨页时出现严重断裂
- 允许横向表格
- 保留原列数、合并单元格和边框结构

## 图片

- 默认保留原尺寸比例
- 不擅自重新裁剪
- 尽量保留文字环绕方式
- 图片段落不使用正文首行缩进
- 输出前检查图片关系是否仍存在

# 十、自动验收

输出后执行：

```bash
python3 scripts/doc_guard.py output.docx
```

检查分为三档：

### 硬错误
- 文件无法打开
- 页面尺寸异常
- 关键版头缺失
- 页码字段损坏
- 版记错误继承页脚

### 风险项
- 字体不存在导致 Word 回退
- 标题层级疑似识别错误
- 表格跨页异常
- 图片锚点可能改变

### 可优化项
- 页面空白偏大
- 标题断行观感较弱
- 个别段落过于拥挤

只有“硬错误 = 0”才视为技术上通过；正式发布前仍建议人工目检。

# 十一、调用方式

## CLI

```bash
python3 scripts/official_doc.py \
  --input 原稿.docx \
  --output "（公文排版）原稿.docx" \
  --title "关于进一步加强工作的通知" \
  --profile official
```

生成红头：

```bash
python3 scripts/official_doc.py \
  --input 内容.md \
  --output 正式文件.docx \
  --profile red \
  --issuer "××市人民政府" \
  --doc-number "×政发〔2026〕12号" \
  --recipient "各区人民政府，市政府各部门：" \
  --author "××市人民政府" \
  --date "2026年8月26日"
```

## Python

```python
from scripts.official_doc import build_document

result = build_document(
    input_path="原稿.docx",
    output_path="（公文排版）原稿.docx",
    profile="official",
    document_type="通知",
)

print(result.report)
```

# 十二、工作完成标准

生成任务只有同时满足以下条件才算完成：

1. 输出文件存在且可重新读取。
2. DOCX 压缩包结构完整。
3. 页面设置符合所选版式。
4. 正文与标题没有明显样式串线。
5. 图片与表格对象关系仍存在。
6. 页码策略通过检查。
7. 版记/红头等已启用要素通过检查。
8. 原始文件没有被覆盖。
9. 检查报告中不存在硬错误。

# 十三、异常处理

### 字体缺失
使用字体别名映射，记录风险项，不把未知字体硬改成另一种语义完全不同的字体。

### WPS/Word 差异
优先生成标准 OOXML；对 Word 私有/版本相关行为降低依赖。发现兼容性问题时以结构稳定为先。

### 原稿结构混乱
先恢复段落结构，再进行视觉排版。不要用大量空格、空段落“伪造对齐”。

### 信息不足
只对格式做合理默认，不虚构机关名称、文号、签发人、日期或密级。
